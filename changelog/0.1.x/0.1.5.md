# 0.1.5 — 2026-08-13

## Added

- **`per_page` / `page_offset`** on `nonprofit_search` output, mirroring ProPublica's pagination metadata when present.
- **Bun install-security scanner** (`bunfig.toml`) — `@socketsecurity/bun-security-scanner` scans every install; `minimumReleaseAge` blocks packages published in the last 3 days, with `@cyanheads/mcp-ts-core` exempted for same-day framework adoption.
- **`.mcpb` native-binding strip** — `scripts/clean-mcpb.ts` and `lint:packaging` now also strip and verify `@duckdb/node-bindings-*` platform-specific entries, alongside the existing agent-doc strip.
- **GitHub community health files** — `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `FUNDING.yml` under `.github/`, and `.gitattributes` for line-ending normalization and generated-file marking.

## Changed

- **`tsconfig.json` split** — typechecks `src/` and `tests/` with `noEmit: true`; `tsconfig.build.json` narrows to `src/` for the actual compile.
- Vendored skills resynced to mcp-ts-core `^0.11.5` conventions.
- Dockerfile adopts BuildKit cache mounts for `bun install` layers and pins the exact Bun patch (`1.3.14`) over a floating minor tag.
- devcheck's outdated-dependency check now tolerates versions held back by `minimumReleaseAge` and skips peer-range rows.

## Fixed

- **`nonprofit_search` state filter** — `state` is uppercased before the ProPublica request and validated against US states, DC, territories, and military codes (plus `ZZ`); an unrecognized value is now rejected as `invalid_state` instead of silently returning unfiltered national results. (#2)
- **`nonprofit_search` empty-page handling** — a zero-match query and a page past the end of the result set are now both successes (empty `organizations`, plus a `notice` distinguishing which) instead of sharing the same `no_results` error. (#5)
- **`nonprofit_search` pagination ceiling** — a page at or beyond ProPublica's 10,000-result offset ceiling is now a non-retryable `pagination_ceiling` error instead of the generic `upstream_error`. (#5)
- **Service-layer error recovery hints** — `nonprofit_get_organization`, `nonprofit_get_filings`, and `nonprofit_search` now attach each tool's own declared `recovery` hint to service-originated `not_found`/`upstream_error`/`pagination_ceiling` throws, not just handler-level ones. (#6)
