# 0.1.8 — 2026-08-25

Framework and dependency maintenance. No tool, prompt, or handler contract in this server changed — every declared parameter, output field, and error contract is what 0.1.7 shipped.

## Added

- **`tests/tools/tool-wire-contract.test.ts`** pins the `CallToolResult` envelope across all three tools: an unrecognized argument key names itself in the rejection rather than being stripped, and a success result's `structuredContent` carries no `error` key while a declared failure carries no success field.

## Changed

- **An argument key no tool schema declares is rejected by name instead of silently stripped.** Previously the key was dropped and the call ran without it; now `tools/list` advertises `additionalProperties: false` and the call fails before the handler runs, naming the key in both `structuredContent.error.message` and `content[0].text`. Strictness is root-level only — a nested object still strips an unknown key.
- **Every tool's advertised `outputSchema` now declares the error envelope** — success fields are optional, `error` is declared — so a client validating `structuredContent` without first checking `isError` stops rejecting error results.
- **HTTP endpoints serve protocol revision 2026-07-28 alongside the 2025 era.**
- **`tools/list` carries a one-hour public cache hint** (`src/index.ts`) — the tool set is fixed at build time with no feature gate or auth scope, so every client is served identical bytes; the TTL bounds how long a cached copy survives a redeploy. Honored on protocol revision 2026-07-28 only.
- **`nonprofit_get_filings`'s PDF-only filing rows** omit the form-type separator instead of rendering a dangling space (`- FY 2009: PDF not available`) when the upstream record has no `formtype_str`.
- **Bun pins move to `1.4.0`** — both `Dockerfile` stages and `packageManager`; `engines.bun` stays `>=1.3.0`. The build stage now carries `--platform=$BUILDPLATFORM` so each leg of the multi-arch image compiles natively.
- **`.env.example` pins `MCP_SESSION_MODE=stateless`,** matching the Docker image — this is a read-only server with no `ctx.requestInput` call site, so nothing needs a durable session.
- **Repo tooling follows the SDK rename** — `scripts/lint-packaging.ts` guards `node_modules/@modelcontextprotocol/server/dist/` in place of the old SDK path, and `scripts/lint-mcp.ts` drops the removed task-handler branch from its tool-shape check.
- **Vendored agent skills re-synced to the 0.12.3 set** — 20 skills, mirrored into `.claude/skills/`.
